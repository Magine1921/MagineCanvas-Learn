# MagineCanvas Agent 升级方案

## 1. 目标

把当前“能调用工具的聊天助手”升级为可靠的生产型单 Agent，并为后续子 Agent、Skills、MCP 和隔离执行预留稳定边界。

目标闭环：

```text
用户目标
  -> 意图路由
  -> 建立持久任务
  -> 规划 / 选择工具
  -> 执行
  -> 验证副作用
  -> 记录检查点
  -> 失败恢复或继续执行
  -> 交付结果与证据
```

## 2. 当前基线

已具备：

- Claude 与 OpenAI 兼容模型的多轮工具调用。
- 画布、文件、网络、API、项目、终端、音乐、即梦和记忆工具。
- 工具权限与高风险操作确认。
- 流式文本、取消任务、会话保存、长期记忆和工作习惯记录。

主要缺口：

- 任务只存在于组件生命周期或内存 Map 中，无法可靠恢复。
- 工具结果主要是字符串，缺少错误分类、产物和验证证据。
- 工具返回成功后没有统一后置条件验证。
- 上下文按消息数量直接截断，没有任务摘要和工具结果压缩。
- 工具模式依赖关键词，存在漏触发。
- 终端没有操作系统级沙箱。
- `sub_agent` 未实现，工具注册仍集中在大型 `switch`。
- 缺少 Agent 专项自动回归测试和完成率指标。

## 3. 目标架构

### 3.1 Agent Run Store

每次用户请求创建一个 `AgentRun`：

- `id`：稳定任务 ID。
- `goal`：原始用户目标。
- `status`：queued/running/waiting/cancelling/completed/failed/cancelled/interrupted。
- `provider/model`：实际执行模型。
- `budget`：轮次、工具数、持续时间和工具输出预算。
- `events`：模型轮次、工具开始、工具结束、检查点、错误、完成。
- `checkpoint`：最近上下文摘要和已完成操作。

运行记录持久化到桌面用户数据对应的浏览器存储。应用重启时把未正常结束的任务标记为 `interrupted`，允许基于已完成事件恢复，并要求先核对当前画布状态，避免重复执行产生二次扣费。

### 3.2 Structured Tool Result

工具统一返回：

```ts
{
  success: boolean;
  message: string;
  data?: unknown;
  error?: {
    code: string;
    category: string;
    retryable: boolean;
  };
  artifacts?: Array<{
    id: string;
    kind: string;
    name: string;
    uri?: string;
  }>;
  verification?: {
    status: "passed" | "failed" | "pending" | "skipped";
    summary: string;
  };
}
```

模型读取的是压缩后的结构化结果；UI 和日志保留完整结果。

### 3.3 Verification Layer

高价值副作用必须验证：

- 节点新增：节点 ID 确实存在。
- 节点删除：节点已经不存在。
- 节点更新：目标字段等于预期值。
- 连线增删：边状态与预期一致。
- 清空画布：节点和连线均为空。
- 文件写入/编辑：重新读取文件检查内容。
- 生成任务：区分“任务已提交”和“素材已生成”，不能把提交成功当成最终成功。

验证失败时把工具结果改为失败，并标记 `POSTCONDITION_FAILED`，交给模型换方案或重试。

### 3.4 Context Manager

- 保留最近高相关消息。
- 把较旧对话压缩为确定性摘要。
- 工具长输出按字符预算压缩。
- 保留原始目标、失败尝试、已完成副作用和产物引用。
- 不再简单依赖最后 50 条消息维持任务状态。

### 3.5 Execution Policy

当前阶段：

- 文件操作限制在项目工作区。
- 终端工作目录限制在项目工作区。
- 拦截不可逆磁盘、系统关机、递归删除根目录等命令。
- 限制命令长度、运行时长和输出大小。
- 子进程环境移除常见密钥变量。
- 高风险工具继续要求确认。
- 网页内容明确标记为不可信数据，不能覆盖系统指令。

最终阶段：

- Windows 受限令牌或独立 Worker 进程。
- 文件写入 ACL、网络域名白名单、子进程树资源限制。
- 每个任务独立工作区或画布事务快照。

## 4. 分阶段实施

### Phase A：可靠执行内核

验收标准：

- 每次请求都有持久 Run ID 和事件轨迹。
- 应用异常退出后任务显示为 interrupted。
- 工具调用具有幂等执行 ID。
- 核心画布与文件工具执行后自动验证。
- 错误包含 category 和 retryable。
- Agent Loop 使用轮次、工具数、时间预算，而不是裸常量。

### Phase B：长任务与上下文

验收标准：

- 较长会话不会直接丢弃原始目标。
- 工具长输出不会无限占用上下文。
- `/resume` 能根据检查点继续未完成目标，并先核对环境状态。
- 取消、失败、完成均有明确终态。

### Phase C：安全与可观测

验收标准：

- 危险命令在 API 层仍会被阻止，不能只依赖提示词。
- 每个工具调用可查看耗时、结果、验证状态和错误类型。
- 可统计成功率、验证通过率、重试率、平均工具数和任务耗时。

### Phase D：扩展与多 Agent

验收标准：

- 工具可通过 manifest + schema + handler 注册。
- Skills 可声明所需工具、说明和验证器。
- MCP 客户端可连接外部工具服务器。
- Planner、Researcher、CanvasOperator、Verifier 使用隔离上下文。
- 并行只用于无写冲突任务，画布写操作串行提交。

## 5. 测试策略

单元测试：

- 运行预算判断。
- 错误分类和重试策略。
- 上下文压缩保留原始目标。
- 工具结果压缩。
- 恢复提示包含已完成与失败步骤。

集成测试：

- 创建、更新、删除节点后验证状态。
- 写入和编辑文件后验证内容。
- 相同 execution ID 不重复执行。
- 取消任务后 Run 进入 cancelled。
- 重启后 running 任务恢复为 interrupted。

产品评测：

- 工具选择正确率。
- 最终验证通过率。
- 重复扣费率。
- 失败自动恢复率。
- 危险操作误执行率。
- 平均耗时、Token 和 credits。

## 6. 完成定义

“模型回答完成”不等于任务完成。只有同时满足以下条件才可进入 `completed`：

1. Agent 不再请求工具。
2. 所有必须执行的工具已结束。
3. 所有关键副作用验证通过，或明确处于可追踪的异步 pending 状态。
4. 最终回复包含已完成内容、未完成内容和必要证据。

## 7. 本轮实施状态

| 阶段 | 状态 | 已落地内容 |
| --- | --- | --- |
| Phase A：可靠执行内核 | 已完成 | 持久化 Run、预算、事件轨迹、结构化结果、执行 ID、核心工具后置验证 |
| Phase B：长任务与上下文 | 已完成 | 历史压缩、工具输出压缩、取消终态、中断恢复与恢复前状态核对提示 |
| Phase C：安全与可观测 | 已完成基础层 | API 层危险命令拦截、工作区路径限制、子进程密钥隔离、输出脱敏、任务历史面板 |
| Phase D：扩展与多 Agent | 已完成第一层 | Skills 注册与选择、受限只读子 Agent、多模态素材分析、三版本同步 |

尚未完成的 Codex 级系统能力：

- Windows 受限令牌、容器或独立 Worker 进程提供的操作系统级沙箱。
- 标准 MCP 客户端、外部 MCP 服务发现与授权。
- 多工作区/工作树隔离的并行子 Agent 调度与写冲突合并。
- 服务端持久任务队列；当前 Run 使用本地持久化，应用关闭期间不会继续执行。
- 覆盖真实供应商、长时间异步生成和崩溃恢复的端到端评测集。
